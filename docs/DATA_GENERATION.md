# CloudCare AI 합성 원천 데이터

실행 파일: `scripts/generate_cloudcare_raw_data.py` (프로젝트 환경 Python 3.12, numpy/pandas/openpyxl).

```powershell
uv run python scripts/generate_cloudcare_raw_data.py
uv run python scripts/generate_cloudcare_raw_data.py --output-dir 'C:\원하는\새폴더'
```

기본 경로는 프로젝트 루트 기준 `data/raw/cloudcare_20260831_seed42`이다. Seed는 42, 사용자 수는 5,000명,
관측 기간은 2024-01-01~2026-08-31이다. 실제 고객 데이터나 개인정보는 사용하지 않는다.
Excel에는 요청된 5.1~5.9 원천 컬럼만 저장한다. 5.10~5.13, 이탈 라벨,
집계 피처, 내부 잠재변수는 생성 또는 저장하지 않는다.

## 결정한 규칙

- 구독 한 행은 같은 요금제가 유지되는 연속 기간이다. 사용자별 기간은 겹치지 않는다.
  요금제 전환은 기존 기간 종료 다음 날 시작하며, 변경 이벤트는 새 구독을 참조한다.
  같은 용량의 월간/연간 상품 간 전환은 생성하지 않는다.
- 구독 수는 82%/15%/3%로 배정한다. 가입 후 90일 이상인 사용자 중 무작위로
  750명에게 2개, 150명에게 3개를 배정하고 나머지 4,100명은 1개를 생성한다.
  이전 구독의 종료 때문에 전체 행의 ACTIVE 비율과 사용자별 현재 ACTIVE 비율은 다르다.
- 구독 취소/만료 후 계정은 유지되고 무료 15GB 수준의 서비스 접근이 가능하다.
  그 기간에 새 무료 구독 행을 추가하지 않는다. 저장량은 해당 한도로 조정한다.
  다운그레이드 시 저장량 감소는 한도에 맞춘 보관량 조정으로 해석한다.
- 월 사용량 키는 해당 월 1일이고, 값은 월말 스냅샷이다. 가입 월의 월 키는 가입일보다
  이를 수 있지만 실제 스냅샷 시각은 가입 이후다. 이전 월 저장량에 성장과 잡음을 누적한다.
- 구독 날짜의 종료일은 포함된다. 결제는 시작일 정오 및 달력상 월/연 기념일 정오에 발생한다.
  월말 기념일은 짧은 달의 말일로 조정하며 다음 달에는 원래 기념일을 다시 기준으로 계산한다.
- `next_billing_date`는 미래 예정일이므로 관측 종료일을 넘는다. 실제 이벤트/결제/로그는
  관측 종료일을 넘지 않는다. 무료 및 종료된 구독의 다음 결제일은 NULL이다.
- RENEW는 관리상 계약 갱신이다. 월간 결제 상품은 3개월마다, 연간 상품은 12개월마다
  발생한다고 가정했다. 결제 성공 여부와 무관하게 생성하며 최초 결제를 RENEW로 세지 않는다.
  무료 상품에는 유료 계약 갱신 이벤트를 만들지 않는다.
- `auto_renewal`은 마지막 저장된 자동갱신 선호 설정이다. 종료 구독에도 과거 설정이
  남을 수 있으나 CANCELLED/EXPIRED 상태가 우선하므로 실제 청구나 갱신은 발생하지 않는다.
- 문의 확률은 마찰·만족도·가입 기간에, 문의 종류는 마찰·재무위험·문의 월 저장률에 연결된다.
  재문의는 기존 티켓의 재개 여부이다. 미해결 티켓은 오래 남아 있을 수도 있다.
- 사용자 상태는 현재 ACTIVE 구독 또는 최근 30일 실제 활동이 있으면 ACTIVE다.
  상태 결정 후 로그 누락을 삽입하므로 관측 로그와 약간의 차이가 있을 수 있다.
- 일부 사용자는 최근 90일 활동과 최근 3개월 저장량이 줄어든다. 이런 사용자의 취소 여부를
  강제하지 않는다. 합성 분포이며 실제 서비스의 이탈률이나 모델 성능을 보장하지 않는다.

## 품질 문제와 검증

정상 데이터 생성 → PK/FK/날짜/업무 규칙 검증 → 결측·누락·이상치·중복 삽입 →
보호 규칙 재검증 → 저장 → Excel 전체 행 재열람 및 메모리 데이터 대조 순서다.

- 월/일 로그 2% 누락; 선택한 측정 컬럼에 0.5% 셀 결측.
- 사용자 지역 1.5%, 연령 0.8%, 가입채널 0.4%, 기기 OS 0.8%, 결제수단 및 문의분류 0.5% 결측.
- 월 사용량 0.7%, 활동 및 결제 0.5%, 문의 0.4% 논리적 중복. PK는 새 번호를 부여한다.
- 활동시간 1.2%에 300~800분, 월 다운로드 1.5%에 3~9배의 큰 값.
- 결제액 0.2%에 10~25% 불일치, 로그인 카운터 0.1%에 -1 오류.
- 요금제 Master, PK/FK, 날짜 및 파일/사진/영상 개수 관계는 훼손하지 않는다.
- `missing_cells`는 정상 NULL까지 포함한다. `inserted_nulls`는 중복 복제 전 의도적으로
  삽입한 결측 셀 수이다. 따라서 둘은 같지 않다. 중복 수는 원본을 제외한 추가 행 수다.

`generation_report.json`에는 파일별 행 수, 컬럼별 NULL 수, 삽입 내역, 검증 결과,
파일 크기와 SHA-256이 기록된다. 이 보고서도 기존 파일이면 보호한다.

## 기존 파일 보호

존재 여부를 저장 직전에 확인하고 `Path.open('xb')`로 배타적으로 생성한다.
동시 실행에서도 기존 파일을 덮어쓰지 않는다. 기존 파일이 일부 있으면 먼저 전체 내용을
이번 seed의 생성 결과와 읽기 전용으로 대조한다. 다른 데이터이면 누락 파일 생성을 중단하여
서로 다른 데이터셋이 섞이지 않도록 한다. 기존 파일은 어떤 경우에도 수정·삭제하지 않는다.
중단으로 생긴 불완전한 파일도 자동 삭제/복구하지 않으며, 새 출력 폴더로 다시 실행할 수 있다.

과거 생성 작업 중간에는 `data/raw` 바로 아래에 5.1~5.4 파일이 남았다는 기록이 있었으나,
2026-09-22 폴더 재검사에서는 해당 파일이 발견되지 않았다. 현재 원천은 위 하위 폴더의 9개 파일이다.
